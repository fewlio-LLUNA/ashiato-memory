# 要件定義書

> `/req-define` の成果物。ユーザー承認後にここで確定。設計の入力になる。

最終更新: 2026-10-21
ステータス: **承認済み**（2026-10-21）

アプリ名（仮）: あしあとメモリー（ashiatomemory）

## 1. 目的・背景
- いま何の業務をしているかをボタン操作で切り替えながら記録し、業務ごとの作業時間を1分単位で正確に残す。
- 会社は工数管理が厳密だが、現状は作業時間を目分量で見積もっており、後から「何をしていたか」が思い出せない。

## 2. ユーザーと利用シーン
- 想定ユーザー: 本人1名（会社員・フレックス勤務）
- 主な利用シーン:
  - 会社PCのブラウザで開いたまま、始業時に「業務開始」を押す（自動で「庶務」の計測が始まる）
  - 作業が変わるたびに業務名ボタンを押して切り替える。該当ボタンがなければその場で新規作成する
  - 昼休憩は「休憩」ボタンで計測する
  - 終業時に「業務終了」を押し、その日の業務別合計を見て会社の工数管理システムへ手で転記する
  - 週・月単位の業務別合計を見返す

## 3. スコープ
### やること（In）
- アプリ内打刻（業務開始／業務終了）
- 業務の切り替え計測（同時に計測するのは常に1業務のみ）
- 業務名ボタンの新規作成・名前変更・非表示（アーカイブ）
- 休憩の計測（工数集計からは除外）
- フレックスの終業目安表示
- 日・週・月の業務別集計表示
- 業務別合計の手動調整（±分）
- データのファイル書き出し・読み込み（バックアップ／復元）
- スマホ幅でもレイアウトが崩れないレスポンシブ表示

### やらないこと（Out）
- サーバー・クラウドへのデータ保存、端末間の同期（PCとスマホのデータは共有されない）
- 会社の打刻システム・工数管理システムとの連携
- 切り替え履歴の時刻・業務の個別編集（調整は業務別合計への±分のみ）
- CSV出力
- 複数ユーザー・ログイン機能
- 外部へのデータ送信全般（解析ツール、外部CDN・Webフォント読み込みを含む）

## 4. 機能要件
| ID | 機能 | 概要 | 優先度 |
|----|------|------|--------|
| F1 | 業務開始打刻 | ボタン押下で当日の勤務を開始し、同時に「庶務」の計測を開始する | MUST |
| F2 | 業務切り替え | 業務名ボタン押下で、計測中の業務を止めて押した業務の計測を始める。計測中の業務はボタン上で一目で分かる | MUST |
| F3 | 業務の新規作成 | 切り替え画面からその場で業務名を入力してボタンを追加し、そのまま計測を始められる | MUST |
| F4 | 業務の管理 | 業務名の変更、非表示（過去の記録は残す）、ボタンの並び順変更 | SHOULD |
| F5 | 休憩 | 「休憩」ボタンで休憩を計測。休憩時間は工数集計に含めない | MUST |
| F6 | 業務終了打刻 | ボタン押下で計測を終え、その日の記録を確定する | MUST |
| F7 | 経過表示 | 計測中業務の経過時間、当日の業務別累計、当日の実労働時間・休憩時間をリアルタイム表示 | MUST |
| F8 | 終業目安 | 終業目安 = 業務開始時刻 + 7時間40分 + 休憩時間（休憩実績が60分未満の間は60分として計算）。残り労働時間も表示 | MUST |
| F9 | 日次集計 | 指定日の業務別合計（1分単位）と切り替え履歴（時刻・業務）の一覧 | MUST |
| F10 | 週・月集計 | 期間（週／月）を選び、業務別合計を表示 | MUST |
| F11 | 合計の手動調整 | 日次の業務別合計に±分の補正を入力でき、集計に反映される（補正値であることが分かる表示） | MUST |
| F12 | バックアップ | 全データをJSONファイルに書き出し、読み込みで復元できる | MUST |
| F13 | 状態の復帰 | ブラウザやタブを閉じて開き直しても、計測中の状態（業務・開始時刻）が継続している | MUST |
| F14 | 打刻忘れ対応 | 業務終了を押し忘れて日をまたいだ場合、次回起動時に前日の終了時刻を入力して確定できる | SHOULD |

## 5. 非機能要件
- セキュリティ／機密性: 記録データ（業務名を含む）は利用ブラウザのローカルストレージ（IndexedDB または localStorage）にのみ保存し、ネットワークへ一切送信しない。外部リソース（CDN・Webフォント・解析タグ）を読み込まない
- 対応環境: 会社PCの主要ブラウザ（Chrome / Edge 最新版）。スマホブラウザ（iOS Safari / Android Chrome）で表示が崩れない
- 性能: 1年分程度の記録でも集計表示が1秒以内
- 正確性: 経過時間はタイマーの積算ではなく、記録した時刻の差分から算出する（スリープ・タブ非アクティブでずれない）
- UI:
  - アイコンは絵文字を使わず、SVGで作成する
  - 角丸は控えめ（最大 4px 程度）
  - メインカラーは群青色と赤色
  - 業務切り替えボタンはPCでもスマホでも押しやすい大きさ

## 6. 制約・前提
- 会社PCには何もインストールできない → サーバー不要の静的Webアプリ（HTML/CSS/JavaScript）とする
- 公開URLの静的ホスティング（GitHub Pages）で配信する。配信されるのはプログラムのみで、記録データは送信されない
- データはブラウザ・端末ごとに独立。ブラウザの閲覧データ削除で消えるため、F12で利用者がバックアップする
- 勤務条件: 所定労働 7時間40分、休憩 1時間（別枠）、フレックス勤務
- 時間の単位は1分（秒は表示上の経過時間のみ）
- 初期業務として「庶務」が存在し、削除できない

## 7. 受け入れ条件（完成の定義）
- 業務開始を押すと「庶務」の計測が始まり、終業目安（開始+8時間40分）が表示される
- 業務ボタンを押すと計測中業務が切り替わり、前の業務の時間が確定する
- 切り替え画面で新しい業務名を入力すると、ボタンが追加され即座に計測が始まる
- 休憩を60分超えて取ると、終業目安がその分後ろへずれる
- ページを再読み込み・ブラウザ再起動しても計測が継続している
- 業務終了後、日次集計で業務別合計（1分単位）と切り替え履歴が見られ、合計 = 実労働時間（補正分を除く）になる
- 週・月集計で業務別合計が見られる
- 業務別合計に±分の補正を入れると集計に反映される
- JSON書き出し → データ削除 → 読み込みで記録が元に戻る
- 開発者ツールのネットワークタブで、ページ読み込み以降に外部への通信が発生していない
- スマホ幅（375px）で横スクロールが発生せず操作できる
- 絵文字アイコンが使われていない
